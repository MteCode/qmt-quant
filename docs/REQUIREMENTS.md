# 需求文档（PRD）

项目代号：**qmtquant** — A 股个人量化交易系统
版本：v0.1
日期：2026-08-26

---

## 1. 背景与目标

个人投资者，在 Windows 本地搭建一套可长期演进的 A 股量化交易系统。已有资源：

- 国金证券 AMT 账号（算法交易平台）
- miniQMT（`xtquant` Python SDK）
- 大 QMT 客户端

**目标**：把"选股逻辑 → 回测验证 → 自动下单 → 风控 → 复盘"整条链路自动化，人只负责策略研发与决策审阅。

**非目标（v1 明确不做）**
- 高频 / 期货 / 期权 / 港美股
- 分布式部署、多用户 SaaS
- Web 前端（先用 CLI + 日志 + 企微/钉钉推送）

---

## 2. 用户角色

| 角色 | 描述 | 关注点 |
|------|------|--------|
| 策略研发者（我） | 写因子、写策略、跑回测 | 回测准确、迭代快 |
| 运维者（我） | 每日启停、监控 | 稳定、不漏单、有告警 |
| 风控者（我） | 设定资金/回撤/单票上限 | 硬约束不可被策略绕过 |

## 3. 功能需求

### FR-1 数据层

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-1.1 | 通过 `xtdata` 下载/增量更新 A 股日线、1分钟、5分钟 K 线 | P0 |
| FR-1.2 | 订阅实时 Tick / 分钟 Bar 推送 | P0 |
| FR-1.3 | 本地持久化（SQLite/Parquet），支持按 `symbol+period+时间区间` 查询 | P0 |
| FR-1.4 | 复权处理（前复权/后复权/不复权可选） | P0 |
| FR-1.5 | 交易日历、停牌/涨跌停/ST 标记 | P0 |
| FR-1.6 | 财务数据、板块成分、指数成分股 | P1 |
| FR-1.7 | L2 逐笔委托/成交落地 | P2 |

### FR-2 策略层

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-2.1 | 提供 `StrategyBase`，回调：`on_init/on_start/on_bar/on_tick/on_order/on_trade/on_stop` | P0 |
| FR-2.2 | 同一份策略代码在**回测**与**实盘**下行为一致（同一套 API） | P0 |
| FR-2.3 | 策略参数外置到 YAML，支持参数网格寻优 | P1 |
| FR-2.4 | 多策略并行，各自独立资金额度 | P1 |
| FR-2.5 | 支持选股型（每日调仓组合）与择时型（单票信号）两类范式 | P0 |

### FR-3 回测层

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-3.1 | 日线/分钟级事件驱动回测 | P0 |
| FR-3.2 | 成本模型：佣金（万2.5，最低5元）、印花税（卖出千1）、过户费、滑点 | P0 |
| FR-3.3 | A 股规则：T+1、100股整数倍、涨跌停不可成交、停牌跳过 | P0 |
| FR-3.4 | 绩效指标：年化、最大回撤、Sharpe、Calmar、胜率、盈亏比、换手率 | P0 |
| FR-3.5 | 输出净值曲线、回撤曲线、交易明细（HTML/CSV 报告） | P1 |
| FR-3.6 | 前视偏差检查（信号只允许用 T 日及之前数据，T+1 开盘成交） | P0 |

### FR-4 交易执行层

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-4.1 | miniQMT 网关：连接、查账户、查持仓、下单、撤单、订单/成交回报 | P0 |
| FR-4.2 | AMT 网关：作为大单算法执行备用通道 | P2 |
| FR-4.3 | 模拟网关（SimGateway）：不接券商，本地撮合，用于联调 | P0 |
| FR-4.4 | 网关抽象统一，策略层无感知切换 | P0 |
| FR-4.5 | 订单状态机与本地订单簿；断线重连后与券商对账 | P0 |
| FR-4.6 | 执行算法：限价/市价/对手价、拆单（TWAP 简版） | P1 |

### FR-5 风控层（硬约束，独立于策略）

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-5.1 | 单笔委托金额上限、单票持仓市值占比上限 | P0 |
| FR-5.2 | 单日最大下单笔数、单日最大成交金额 | P0 |
| FR-5.3 | 账户日内亏损阈值 → 触发只平不开 | P0 |
| FR-5.4 | 禁止买入黑名单（ST、退市风险、次新、停牌） | P0 |
| FR-5.5 | 可用资金校验、可卖数量校验（T+1 冻结） | P0 |
| FR-5.6 | 全局急停开关（Kill Switch），一键撤单+停止下单 | P0 |

### FR-6 运维与监控

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-6.1 | 分级日志，按日切分，交易日志单独归档 | P0 |
| FR-6.2 | 关键事件推送（下单/成交/风控拦截/异常）到企微或钉钉机器人 | P1 |
| FR-6.3 | 每日盘后自动生成持仓与盈亏报告 | P1 |
| FR-6.4 | 定时任务调度：盘前数据更新 → 开盘运行 → 盘后结算 | P1 |
| FR-6.5 | 崩溃自动重启 + 状态恢复 | P2 |

## 4. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | Tick 处理延迟 < 50ms；日线回测 300 只 × 5 年 < 60s |
| 可靠性 | 交易时段无未捕获异常导致进程退出；订单不重复、不丢失 |
| 可维护性 | 模块解耦，网关/策略/风控可独立替换；核心逻辑单测覆盖 |
| 安全性 | 账号、资金账号、Token 不入库不入 git；`config/*.yaml` 加入 `.gitignore` |
| 环境 | Windows 10/11 x64，Python 3.11，miniQMT 客户端需常驻登录 |

---

## 5. 关键约束与风险

| 风险 | 影响 | 应对 |
|------|------|------|
| xtquant 为闭源 SDK，版本更新可能破坏 API | 实盘中断 | 网关层隔离，锁定 SDK 版本，升级先在模拟盘验证 |
| miniQMT 客户端掉线 | 下单失败 | 心跳检测 + 自动重连 + 告警；大 QMT 手工兜底 |
| 回测与实盘不一致（滑点、成交概率） | 实盘亏损 | 保守成本模型；先小资金实盘跑 1 个月验证 |
| 策略过拟合 | 实盘失效 | 样本外测试、参数平原检查、滚动前推验证 |
| 单机断电/断网 | 持仓失控 | 风控设置服务端条件单兜底；重要仓位设硬止损 |
