# ALSTM 选股 + PPO 择时 · 中证 1000

两个模型串联：**ALSTM 决定买哪些，PPO 决定买多重。**

| 模型 | 产物 | 输入 | 输出 |
|------|------|------|------|
| ALSTM | `models/alstm_scores.parquet` | Alpha360（6 特征 × 60 天） | 全市场打分，取 Top-K |
| PPO | `models/ppo_model.zip` | 市场聚合特征（11 因子的均值+标准差）+ 组合状态 | 仓位比例 [0, 1] |

两者**没有耦合**：PPO 的状态里不含 ALSTM 分数，它是在等权全市场上训练的。
换掉分数不影响 PPO 行为，但组合结果会变 —— 所以换分数后必须重跑回测。

## 回测结果（2022-01-04 ~ 2026-08-27，样本外）

| 指标 | 值 |
|------|-----|
| 总收益 | +44.37% |
| 年化收益 | +8.72% |
| 最大回撤 | 14.34% |
| 年化波动 | 8.65% |
| Sharpe | 1.008 |
| 平均仓位 | 29.9% |

⚠ **这个成绩单对应的是旧版 ALSTM 分数，已在 2026-09-01 22:32 被重训覆盖。**
当前 `models/alstm_scores.parquet` 是新模型（IC 0.0276 / t=7.23，优于旧版
0.0177 / t=4.72），但**这个新组合从未回测过**。旧分数没入库，已永久丢失。
继续实盘前应先跑一次 `train_ppo.py` 拿到当前组合的真实成绩单。

## 目录结构

```
alstm_ppo_csi1000/
├── strategy.yaml       策略参数（持仓数、调仓周期、本金）
├── paths.py            路径解析，所有脚本从这里取路径
├── train_alstm.py      训练 ALSTM，产出分数面板
├── train_ppo.py        训练 PPO + 组合回测
├── generate_signal.py  每日信号：选股 + 定仓位
├── paper_trade.py      读信号下单（过风控）
├── risk_monitor.py     盘中守护，触线自动减仓/清仓
├── daily_pipeline.py   一键：更新数据 → 生成信号
├── scheduled_trade.py  定时：09:00 更新 / 09:15 信号 / 09:31 下单
├── models/             模型产物（走 Git LFS）
├── backtest/           回测结果 CSV
├── signals/            每日目标持仓
└── state/              运行时状态（回撤峰值等）
```

风控参数**不在** `strategy.yaml` 里，走全局 `config/config.yaml` 的 `risk` 段，
回测与实盘共用同一份，避免两边漂移。

## 日常运行

开盘前挂上定时脚本，它会按点执行：

```bash
python strategies/alstm_ppo_csi1000/scheduled_trade.py --dry-run
```

| 时间 | 动作 |
|------|------|
| 09:00 | 更新行情 |
| 09:10 | 导出 Qlib |
| 09:15 | 生成信号 |
| 09:31 | 下单（避开集合竞价） |

另开一个窗口跑盘中风控守护：

```bash
python strategies/alstm_ppo_csi1000/risk_monitor.py --dry-run
```

确认无误后去掉 `--dry-run` 才会真实下单/减仓。

## 风控

三档回撤控制与回测共用 `DrawdownController`，阈值读 `config.yaml`：

| 档位 | 回撤 | 动作 |
|------|------|------|
| 一档 | 6% | 停止开新仓，存量不动 |
| 二档 | 9% | 减仓至 30% |
| 三档 | 12% | 全部清仓 |
| 日亏线 | 3% | 当日只平不开 |

**两条时间线**（见 `risk_monitor.py` 模块文档）：档位控制器每个交易日只喂
1 个观测点，因为 `min_observations=20` / `max_freeze_observations=120` 是按
日线扫出来的参数，秒级喂会让「120 天冻结期」退化成「1 小时」。日内连续跑的
是 3% 日亏线。

实测回撤控制对本策略的影响（回放 PPO 净值曲线）：

| 配置 | 收益 | 最大回撤 | 触发次数 |
|------|------|---------|---------|
| 不加控制 | +44.37% | 14.34% | — |
| 6/9/12 | +46.40% | 11.98% | 3 |

4.5 年只触发 3 次，收益差异属噪声。结论是**基本不花钱**，不是"能赚钱"。
本策略年化波动仅 8.65%，一档 6% 是 0.69 倍波动率，高于 `drawdown.py` 给的
0.5 倍经验下限，所以档位对它偏宽松。

## 重训注意

`train_alstm.py` 会**覆盖** `models/alstm_scores.parquet`。覆盖前先提交，
否则旧分数找不回来（神经网络随机初始化，重训不会得到相同模型）。

```bash
git add strategies/alstm_ppo_csi1000/models/ && git commit -m "chore: 保存重训前的模型产物"
```

重训 ALSTM 后**必须**重跑 `train_ppo.py`，否则手上的回测数字描述的不是正在
跑的系统。

## 已知偏差：回测没有整手约束

回测按「权重 × 收益率」计算，不模拟真实下单。实盘必须 100 股整手买，
50 万 × 46% 仓位分 30 只 = 每只 7,668 元，股价超 76 元的票连 1 手都买不起
会被跳过。所以 `hold_k` 从回测的 30 降到实盘的 10（每只约 23,000 元）。

**这意味着实盘持仓数与回测不一致，分散度下降，波动会比回测大。**
